## 2. APIs

`W/ui/dialog.js` (91 lines)
- `confirmAction(t, { title, lines = [], confirmLabel } = {})` `dialog.js:75-90` -> Promise<boolean>. `title` = h2; `lines` = `<ul class="dialog-lines">` of `<li>`; cancel button first and autofocused (`:22-35`); confirm button label default `t("common.confirm")`. There is NO `tone` option: confirm button is always `button button-primary` (`:35`). A "consequence sentence" = put it in `lines` (the established pattern: one line, e.g. `stage.stop.line`). No input field (cannot take a reason; `askSecret` `:46-72` is the only input dialog, password type).
- Rendering needs `document.body`, `<dialog>.showModal()`; resolves on `close` event via `openDialog` `:8-23`.

`W/ui/section.js` `confirmedButton(ctx, { label, title, lines = [], tone = "quiet", run })` `section.js:193-209` -> `<div class="action">button + errorBox</div>`. `tone` only selects the *trigger* button class (`button-${tone}`, e.g. "danger" in round.js:76). Click: hide error box -> `confirmAction(ctx.t,{title,lines,confirmLabel:label})` -> disable button, `await run()`, catch -> `showErrors(box, error, ctx)`, finally re-enable. Currently used once (`round.js:76`). Not usable inside a simpleForm onSubmit (it is a standalone button).

`stage-actions.js` has its own `actionButton(env,{label,tone,ask,run})` `:60-77` (`ask` object or function returning `{title,lines}`; calls accepted() notify + `env.onChanged()` after; refusal handling incl. state conflict). `PLAIN.<x>.ask: true` builds `{title: t("stage.<x>.title"), lines: plainActionLines}`. So Start confirm = add `ask: true` + i18n `stage.start.title/.line` (and `plainActionLines` already uses `stage.${name}.line`).

Pattern for confirming inside a form: onSubmit of simpleForm may `await confirmAction(...)` and `return` early on cancel (see `round.js:62`, `safety.js:84` which throws `notApproved` ApiError so the form shows a refusal instead). CAUTION: `simpleForm` (`ui/forms.js:331-370`) calls `showStatus(status,[t("form.done")],"ok")` after onSubmit resolves, so a bare `return` on cancel still shows "Done." (this already happens for the round abort path). Safer: throw an `ApiError(0,"not_approved",msg)` like safety.js:67-70/85 or add a cancel sentinel. The form also drafts: `keepDraft` only on failure.

Tests driving confirm dialogs: **none exist.** `grep dialog|showModal|confirmAction` in tests/web finds only `config-pages.test.mjs:137,142` and `stage-status.test.mjs:120-132` which test the *line builders* (`plainActionLines`, `irrigationPrompt`, `abortLines`, safety diff lines) and never click through. `tests/web/support/fake-dom.mjs` (388 lines) has no `showModal`/dialog support (no match for showModal|dialog|close). Tests drive forms with `form.dispatchEvent(new Event("submit"))` (`project-page.test.mjs:38-43` `submit()` helper with `formControls(form).set(values)`) and buttons with `.dispatchEvent(new Event("click"))` (`stage-status.test.mjs:151`). Pattern for testing a confirm: export a pure builder (like `irrigationPrompt`, `abortLines`, `plainActionLines`) and assert text; to click through, a test would need to stub `HTMLDialogElement.showModal` in fake-dom or install a `document.body`-level auto-confirm stub (new support code).

1. Start disabling needs a server read (approval info) - not derivable from stage state (stage stays `pending_review` after approve).

3. `ui/forms.js` needs `min`/`max` (and probably checkbox) support for STG-16/STG-17/EVI-02; simpleForm shows "Done." after a cancelled confirm unless the cancel throws an ApiError.
4. Configured pump cap default is 5 s (<60): consider reading `max_pump_seconds` (exposed at `api.py:176`) rather than hard-coding 60.
5. Add fake-dom dialog support before changing tests.
