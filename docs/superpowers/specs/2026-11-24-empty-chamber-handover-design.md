# 空舱交接：释放确认、空闲设置与释放后的读数归属：设计

**日期：** 2026-11-24 · **状态：** 待批准 · **前置：** 多用户与温室锁定（`2026-11-16-multi-user-locks-design.md`）

标注：**[用户]** = 用户明确表态；**[设计方]** = 设计方的决定，审阅时可推翻；未标注 = 由现有代码直接推出。

## 1. 意图

现场核实：舱里的植物是使用者自带的，实验结束后自己搬走，交接时只剩空舱 **[用户]**。多用户层原先默认植物常驻舱内，有三处与此不符：

1. **释放时设备保持当时设置。** 释放只交还养护写入权，不写设备（`workflow/locks.py`）。释放时养护正开着灯，空舱就一直亮到下一个人启动阶段。适配说明第 6 条把"释放时设到空闲状态"留作待办。
2. **释放后的读数仍记在上一个实验下。** `WorkflowStore.active()` 取"最近启动、所在轮次未交付"的阶段，`runtime._ingest` 把新读数记进它的实验。释放之后、下一个阶段启动之前的读数（包括下一位使用者锁定、搬入植物、准备期间的读数）都记进上一位使用者的实验；上一个项目的日报也照常生成。
3. **释放不要求确认舱已清空。**

正确流程是**先搬走植物，再释放** **[用户]**。有人可能偷懒先点释放再来搬 **[用户]**，所以释放时要求明确确认，释放即代表舱已空。

## 2. 目标、非目标、反目标

**目标**

- G1 使用者释放温室时必须确认"植物已搬走"，服务端强制，记入锁定日志。
- G2 温室没有当前阶段时，设备保持管理员配置的空闲设置；断连、进程重启后自动补上。
- G3 释放后该温室没有"当前阶段"：读数不记入任何实验，上一个项目的日报停止，执行器转入空闲。

**非目标**

- 网页上编辑空闲设置（写在配置文件里，由部署者维护）。
- 判断舱里是否真的有植物（没有能判断的传感器），靠使用者确认。
- 改阶段结束后的养护规则：从阶段结束到搬走植物之前，养护照常维持植物 **[设计方]**。
- 管理员强制释放的确认：管理员现场判断，强制释放已要求备注，不加勾选 **[设计方]**。
- 多设备接入、Argus/Titan 接入。

**反目标**（做成这样就算失败）

- 空闲设置打开水泵，或与保护规则争同一通道。
- 阶段启动之后还有空闲写入落到设备上。
- 释放后的读数、日报出现在上一位使用者的项目里。
- 未配置空闲设置的部署，除释放确认与 G3 外行为有任何变化。

## 3. 约束

- 写设备只经 `ControlService` 与写入权；执行器不能打开水泵（`executor/engine.py` 的 `_write`）。
- 一个进程仍只控制 `settings.device` 一台设备；配置与写入按 `device_id` 组织，不堵多设备。
- `workflow/store.py`（816 行）与 `workflow/service.py`（863 行）已超过 800 行，新增逻辑放新模块或现有小模块，不再往这两个文件里加实质内容。
- 测试沿用 `SimulatedTransport` 与现有 e2e 方式。

## 4. 方案比较

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| A 释放时写一次 | 释放：交还养护 → 写空闲设置 → 回读确认 → 删锁 | 逻辑集中在释放；但释放时断连要么卡住使用者、要么留下旧设置，写到一半崩溃要专门恢复（原设计第 2 轮审查卡在这里） |
| **B 无当前阶段时对齐空闲设置（选定）** | 执行器每个周期像养护规则一样把设备对齐到空闲设置；释放本身不写设备 | 断连、重启后自动补上，不需要释放与写设备之间的事务协调；执行器要多一个分支，工作流要多管一个写入权 |
| C 只改流程 | 要求运行单的结束动作全关，释放页加提示 | 管不住释放时养护正开着设备的情况，也不解决读数归属 |

用户选 B **[用户]**。

## 5. 设计

### 5.1 释放确认

- `POST /wb/greenhouses/{greenhouse_id}/release` 增加请求体 `{"plants_removed": true}`。缺少或不为 `true` 时拒绝，新拒绝码 `plants_not_removed`（在 `codes.py` 和中英文案里登记），锁不动 **[用户]**。
- 锁定日志里的这次 `release` 记录写明已确认 **[设计方]**。
- 控制台温室页的"释放"改为确认框：勾选"植物已搬走、舱已清空"后才能提交；说明释放后养护停止、设备转为空闲设置、之后的读数不再记入你的实验 **[设计方]**。
- 管理员强制释放（`POST /wb/admin/greenhouses/{id}/release`）不变。

### 5.2 释放后没有当前阶段

- `WorkflowStore.active()`（从而 `active_stage()`）对已随释放结束养护的阶段（`care_released`）返回 `None`，两处口径一致；下一个阶段启动后恢复正常 **[设计方]**。`release_care_of_device` 已在释放事务里标记该设备所有已结束阶段，释放要求设备上没有未结束阶段，所以被标记的阶段不会再运行。
- 由此带来的变化都是要的：`_ingest` 不给读数标实验；日报不再为上一个项目生成；阶段检查、读数冻结检查、观察者不再按那个阶段算；环境页没有当前阶段；执行器进入空闲分支（5.3）。
- 实现前逐个核对调用点，确认没有依赖"释放后仍返回旧阶段"的地方：`runtime.py`（`_ingest`、日报、第 520 行）、`runtime_agents.py`、`agents/handlers_orchestrator.py`、`workbench/environment.py`、`workflow/recovery.py`（直接用 `store.active()`）、`observer/stage_checks.py`、`observer/frozen_watch.py`、`observer/service.py`、`executor/engine.py`。
- 例外：审计员的"阶段结束审计"仍要能找到刚释放的阶段（释放可能早于模型循环下一次运行），所以 `active_stage(include_released=True)` 只给它用 **[设计方，核对调用点时补充]**。
- 已知精度：读数按入库时有没有当前阶段判断，释放前几秒收到、释放后才入库的读数不记实验；释放时还没生成的日报（例如阶段最后一天的）不再补发。可以接受 **[设计方]**。

### 5.3 空闲设置

**配置** **[设计方]**

- `Greenhouse` 增加可选字段 `idle`：通道到档位的映射，只允许 `light`（0–100）、`exhaust`（0–100）、`fan`（0–10），写 `pump` 时配置校验报错；省略表示不启用。
- 未配置 `greenhouses` 时的隐式单温室，从 `Settings` 顶层新增的 `idle` 取值。
- 例：

```toml
[[greenhouses]]
id = "gh-01"
name = "Chamber 1"
device_id = "ac5-01"
idle = { light = 0, exhaust = 10, fan = 0 }
```

**何时生效**

- 本机设备配置了空闲设置，且没有当前阶段（5.2 之后：从未启动过阶段，或已释放）。
- 锁定之后、阶段启动之前仍保持空闲：这段时间锁定人本来也不能写设备，舱保持空闲直到他的阶段接管 **[设计方]**。
- 不看 `multi_user` 开关：空闲设置默认不配置，配置了就按上面的条件生效。

**写入权**

- 工作流为设备持有一个**空闲写入权**，只能写配置里列出的通道与档位（和养护写入权一样按档位列表限定）。
- 签发：进程启动（与 `restore_care` 同处）和释放完成之后，若没有当前阶段即签发。
- 交还：阶段启动时，和交还养护写入权在同一步里交还（控制服务交还时作废排队写入），保证启动之后没有空闲写入落地。
- 配置里的空闲设置变了（重启后）就按新档位签发。

**执行器**

- 执行器经 `StagePort` 取空闲写入权编号与档位（没有就是 `None`），不直接读锁表或配置。
- 每个周期在中断联锁、水泵看门狗、保护规则之后、`stage is None` 的提前返回之前：若没有当前阶段、设备在线且持有空闲写入权，按空闲档位对齐。
- 跳过保护规则正占用的通道（`_protected()`），跳过水泵。
- 沿用养护的对齐方式：每个相位确认一次，没确认的下个周期重试，回读连续失败的通道按现有上限停手。断连期间写不进去，恢复后补上；重启或空闲写入权换号后重新对齐。设备上被人手动改过的设置不会在同一相位内被改回 **[设计方]**。
- 写入不带实验与阶段（`owner = "device"`），触发记为 `idle:<通道>`，在操作记录里可查。

## 6. 测试

- 释放：不带 `plants_removed` 或为 `false` → `plants_not_removed`，锁仍在；带 `true` → 释放成功，日志记有确认。管理员强制释放不需要它。
- 释放之后：`active_stage()` 为 `None`；新读数不带实验；日报不为上一个项目生成；环境页没有当前阶段。
- 空闲对齐：释放后设备到达空闲档位并回读确认；释放时断连 → 恢复连接后补上；空闲期间重启 → 重新签发并对齐；保护规则占用排风时不写排风；从不写水泵。
- 阶段启动：启动之后没有空闲写入落地（交还时排队的空闲写入被作废）。
- 未配置空闲设置：释放后不写设备，其余行为与现在一致。
- 一个 e2e：锁定 → 阶段运行 → 结束 → 勾选释放 → 空闲 → 下一位锁定、启动阶段 → 读数记进新实验、旧项目里没有中间这段读数。

## 7. 留给实现者

- 空闲写入权复用养护写入权种类（阶段为空），还是新增一种；它的编号存在哪里。
- 执行器存储保护（`allow(kind)`）是否需要新的写入类别。
- 锁定日志里确认的记录形式（备注文字或新列）。
- 相位键加入空闲写入权编号的具体做法。
