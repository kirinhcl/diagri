# 记忆 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 模型角色开工时拿到本项目前几轮的结论与人的决定、设备上反复出现的异常和人写的说明；人可以在控制台写设备日志和已读原因。

**Architecture:** 记录层补三处（`wf_round_choices`、报告的 `holdout_id`、`alert_notes` + `device_notes`）；两个纯读模块算出记忆：`agents/memory_rounds.py`（研究历史）和 `observer/episodes.py`（经历与规律）；`agents/memory.py` 组装 `history` 并裁剪，接入 `project_context` 的调用点和一个只读工具；工作台加两组路由和控制台两个小入口；日报加一节。全部只读既有数据，不改执行层与任何判断。

**Tech Stack:** Python 3.11+ / FastAPI / pydantic v2 / SQLite（`Database.migrate` 同一命名空间只能追加步骤）；控制台为原生 ES 模块，Node 20 `node --test`。

**Spec:** `docs/superpowers/specs/2026-11-17-memory-design.md`

## Global Constraints

- 模型只读记忆：不新增任何让模型写日志、写已读原因或改记录的工具。
- 不改执行层、保护规则、告警规则、阶段检查和审计的判断。
- 研究历史只取任务所属项目；别的项目的轮次按"不存在"回答（`Denied("state", f"unknown round {round_id}")`，与 `WorkflowStore.round` 一致）。
- 报告三种降级（按此顺序判断）：文件读不到或 `file_digest(path) != artifact.sha256` → `{"unavailable": true}`；失效 → `{"invalid": true, "label": ...}`；用过保留集 → `{"held_out": true, "label": ...}`。降级后不带结论、效应、p 值。
- **失效的判断**：`archive.is_invalid(artifact.id)`、`is_invalid(artifact.snapshot_id)`，以及报告 JSON `evidence_chain` 里每个 `"snapshot:<id>"` 的 `is_invalid(<id>)`，任一为真即失效。发布时一份报告可以合并多个快照，但只把最弱的一个登记为 `artifact.snapshot_id`（`handlers_report.py` 的 `weakest`），`mark_dependents_invalid` 只经它找报告，其余快照失效不会标到报告上。
- 经历：`protection` 与 `data_gap` 只取本项目阶段运行窗口内；`frozen` 跨项目，但 `multi_user` 开启且不在本项目窗口内时去掉 `value`。
- **截止时间 `now` 贯穿所有经历计算**：阶段窗口的右端取 `min(结束时刻, now)`；卡住期 `last_at > now` 或 `closed_at > now` 时按"截止时仍开着"处理（`end = None`，原因只关联到 `now` 之前）；缺口只读 `≤ now` 的样本；保护写入只取 `created_at < now`。日报补发昨天的报告时不得用到今天才知道的数据。
- 常量：`MAX_ROUNDS = 5`、`MAX_DECISIONS = 8`、`MAX_LIMITATIONS = 3`、`EPISODE_DAYS = 7`、`NOTE_DAYS = 30`、`MAX_PATTERNS = 10`、`MAX_EPISODES = 10`、`MAX_NOTES = 5`、`HISTORY_CHARS = 6000`、`MERGE_SECONDS = 900`、`GAP_MIN_SECONDS = 1800`、`RECUR_DAYS = 3`、`RECUR_SPREAD_SECONDS = 7200`、`NOTE_MAX = 500`、日报 `MAX_RECURRING_LINES = 3`。
- 裁剪顺序：`episodes` → `notes` → 各轮 `decisions` → `patterns` → 最后才动 `rounds`。
- 迁移只追加步骤；`wf_round_choices` 追加在 `workflow/store.py` 的 `STEPS` 末尾，`alert_notes` 追加在 `observer/alerts.py` 的 `STEPS` 末尾，`device_notes` 用新命名空间 `"device_notes"`（库 `dbs["observer"]`）。
- 代码限制：文件 ≤ 800 行，函数 ≤ 30 行，嵌套 ≤ 3 层，分支 ≤ 3 个。`runtime.py`（773 行）净增 ≤ 8 行，装配写进 `runtime_agents.py`。
- 门禁（不接管道，用 `&&` 串）：`.venv/bin/ruff check -q src tests && .venv/bin/ruff format --check -q src tests && .venv/bin/python -m pytest -q -p no:cacheprovider && node --test tests/web/`。定向跑时 `tests/e2e` 与 `tests/observer` 分两次（两处 `conftest` 同名，一次收集会冲突）。

## Review Focus

1. **记忆出错不能拖垮任务**：报告文件被删、JSON 损坏、某张表缺列时，任务照常开工，`history` 只带 `{"error": "history unavailable"}`。→ Task 6 `test_history_failure_does_not_stop_the_task`。
2. **用别的项目的轮次编号调工具**：回答与不存在的编号逐字相同。→ Task 7 `test_other_project_round_reads_as_unknown`。
3. **跨午夜和仍开着的卡住**：23:30 与 00:10 开始的经历算同一时段；仍开着的卡住不参与时长中位数。→ Task 5 `test_starts_across_midnight_cluster`、`test_open_frozen_has_no_duration`。
4. **说明很多、很长**：30 条 500 字的设备日志加 10 轮决定，`history` 仍 ≤ 6000 字符、仍是合法 JSON、`rounds` 的报告摘要还在。→ Task 6 `test_trim_keeps_round_reports_last`。
5. **新增字段之前的报告**：项目登记过保留集、报告 JSON 没有 `holdout_id` 键 → `held_out`；项目没登记过 → 正常给数。→ Task 4 `test_old_report_in_holdout_project_is_held_out`。

  - `recurring_lines(found: Sequence[Pattern]) -> tuple[str, ...]`：只取 `recurring`，≤ `MAX_RECURRING_LINES`，英文一行，例：`"protect:hot on 4 of the last 7 days, around 14:05"`。

规则（照 spec 5.3）：
- 保护：`archive.actions(experiment_id)` 里 `trigger.startswith("protect:")`、`created_at` 在本项目窗口内且 ≥ `since`；同一规则相邻写入间隔 ≤ `MERGE_SECONDS` 并成一次；`end = None`。
- 卡住：`archive.frozen_periods(since, now)`，`start = first_at`、`end = last_at`（截止规则见 Global Constraints）；`in_project` = 与任一本项目窗口有重叠；`hide_values and not in_project` → `detail` 不带 `value`。
- 原因的关联用**检测时间轴**，不用样本时间轴：卡住期的 `opened_at` / `closed_at`（`frozen_marks.recorded_at`，与告警同为 `clock.now()`）对 `book.notes_of("frozen_reading", sensor)` 里告警的 `first_at` / `resolved_at`；两区间（未关闭端取 `now`）重叠即挂上。样本时间（`first_at` / `last_at`）只用于经历的开始、结束和规律统计。
- 缺口：每个窗口内 `archive.samples(stage.experiment_id, a, min(b, now))` 配 `run_sheet.sampling.max_gap_seconds` 求 `coverage_gaps`，只留 ≥ `GAP_MIN_SECONDS`。
- 规律：近 `EPISODE_DAYS` 天、`start < now` 的经历按 `(kind, subject)` 分组；同组首尾间隔 ≤ `MERGE_SECONDS` 的先串成一次"发生"（无 `end` 的按 `start` 算）；`typical_start` 用环形中位数（下面算法）；`recurring = days >= RECUR_DAYS` 且每次开始与中位数的环形距离 ≤ `RECUR_SPREAD_SECONDS`；`typical_minutes` 只用有 `end` 的发生，没有则 `None`。

```python
def circular_median(seconds_of_day: Sequence[float]) -> float:
    """The point of the 24 h circle with the least summed circular distance to the starts
    (ties: the earliest); candidates are the starts themselves."""
    day = 86400.0
    def spread(c: float) -> float:
        return sum(min(abs(s - c), day - abs(s - c)) for s in seconds_of_day)
    return min(sorted(seconds_of_day), key=spread)
```
